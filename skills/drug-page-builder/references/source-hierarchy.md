# 信息来源层级与数字登记（S1–S5）

药品页是 YMYL 页面：每个事实都要能回答「这条信息来自哪一层、什么时候核过」。本文件定义来源分层、冲突裁决和数字单一真相源。**先研究来源，后写作**；卡面、正文、FAQ、结构化数据里出现的每个数字，都必须能落到一条登记。

## 一、五层来源与各自管什么

| 层 | 来源 | 唯一有资格回答 | 取证方式 |
|---|---|---|---|
| **S1 说明书** | NMPA 批准说明书（中国医药信息查询平台、药监数据库镜像）、FDA/DailyMed 英文说明书 | 适应症、用法用量、剂量调整、不良反应及发生率、禁忌、相互作用、特殊人群、药代、贮藏、批准文号 | 说明书是法律文本，逐字段抄录后加「对患者意味着什么」的一句白话解释 |
| **S2 监管与支付** | 国家医保局、省级医保局文件、国家基本药物目录、NMPA 获批公告 | 医保乙类/甲类、限定支付范围、支付标准、集采、基药目录、获批时间线 | 政府文件原文优先；省口径要写清是哪个省、哪一年 |
| **S3 研究原文** | NEJM/Lancet/JCO 原文（带 DOI）、ClinicalTrials.gov 登记页 | PFS/OS/ORR、中位耐药时间、亚组数据、样本量、研究设计 | 只引原文；二手转述的数字必须回原文核对 DOI |
| **S4 指南与共识** | CSCO、中华医学会诊疗指南、专家共识（如耐药检测路径） | 治疗线次定位、检测路径、指南推荐等级 | 注明版本年份；指南口径与说明书口径不一致时两者都写 |
| **S5 价格实况** | 政府门户网站披露价、省级采购平台、权威媒体 | 当前零售价、报销后自付测算 | 价格必须带年份与口径；媒体价只能作线索，要回 S2 找官方文件 |

**SERP（下拉词）只证明需求存在，永远不是事实来源。**「奥希替尼医保报销后价格」上卡面是因为搜索的人多（需求证据），卡面答案的数字来自 S2/S5（事实证据），两套证据分别登记、不可互替。

## 二、冲突裁决

1. **同一事实两个来源打架**：先查是不是口径不同——发生率的分母（说明书汇总 1813 例 vs 单项研究 833 例）、年份（2022 续约价 vs 2026 媒体口径）、比例方向（报销比例 vs 自付比例）。口径能区分就并列写清口径，不能区分才信高层级来源。
2. **各层权威序**：用法用量与安全警示信 S1；疗效数字信 S3；报销与目录信 S2；路径推荐信 S4；价格信 S2，S5 只兜底。不要跨层借用：指南推荐的超适应症用法不能写成「说明书批准」。
3. **「医保支付范围 = 说明书适应症」是高危断言**。国谈药限定支付范围通常**窄于**批准适应症；没有医保局原文佐证时，降级写「报销范围以参保地公示为准」。
4. **只有媒体来源的关键事实**（如「进基药目录」）属 YMYL 高风险：写进 `titleTag`、字段或正文之前必须补到政府文件级来源，否则不进页面。
5. **拿不到权威口径时如实写不确定性**，这是加分项不是缺陷。已验证的写法：「呕吐后是否补服，说明书没有规定」「2026 年官方支付标准未公开」「中美说明书口径差异」「国产仿制药两种价格口径并存」。禁止编一个数字填空。

## 三、numbers.json 数字登记表（单一真相源）

每药在 `src/content/audit/<slug>/numbers.json` 登记全页数字：

```json
{
  "entries": [
    {
      "name": "腹泻发生率",
      "value": "约 47%",
      "anchor": "腹泻",
      "basis": "说明书汇总安全性数据（1813 例单药）",
      "source": "甲磺酸奥希替尼片说明书",
      "kind": "label",
      "checked_at": "YYYY-MM-DD",
      "used_in": ["labelFacts·常见不舒服", "正文副作用表", "FAQ·最常见的副作用"]
    }
  ]
}
```

规则：

1. **凡是会出现在≥2 处的数字必须先登记再使用**：发生率、报销比例、价格、中位 OS/PFS、疗程、耐药时间。一处改数、全页跟着改，靠登记表核对而不是靠记忆。
2. **卡面、正文、FAQ、`labelFacts`、JSON-LD 是同一个数字的五个副本**，任何两处不一致即 P0 缺陷。已发生过的事故：FAQ 写「皮疹约 58%、腹泻约 42%」，正文与卡面写「腹泻约 47%、皮疹约 46%」——数字互斥且排序相反，FAQ 还被结构化数据抓取放大。
3. `used_in` 记录每个副本位置；`value` 必须是页面里出现的**字面写法**（校验脚本按字面在页面找，找不到即报错）。
4. `anchor` 是页面里**紧接该数字之前的短语**，脚本用它扫描：同一锚点后面出现登记表以外的数字即报口径冲突。锚点要选得足够具体——「对照组为」会同时命中两个研究的对照臂，写成「个月**，对照组为」才只指 LAURA；宁可多写几个字。不加 `anchor` 时脚本退回用 `name` 前缀猜测，容易把「居民约」「研究中」这类两字词当锚点误报。
5. 并列的近似口径（直答卡「不到 1000 元」/ stat-band「700–1200 元」/ 折算表「745 元、993 元」）不算矛盾，但**同一锚点下逐条登记**，并在 `basis` 写明哪个是约数、哪个是哪省算例。同名不同口径的数字（如报销 85% 与生存率 85%）用不同锚点分开登记。

## 四、来源标注的三个层级

- **卡面 `source`**：单条结论的出处（「甲磺酸奥希替尼片说明书（用法用量」这种到字段级）。
- **节末 `.source-note`**：整节的口径来源，每节一条，14px 细线上置。
- **frontmatter `sources[]`**：全页来源列表（≥15 条、一手 ≥5），带 `kind`（label|guideline|trial|regulatory|price|other）供 JSON-LD 分组。

DOI、政府链接在收录前逐条实测可达性。NEJM 403 / NMPA 412 是反爬不是死链；NXDOMAIN 才是要替换的死链。引用研究必给正确 DOI——错误 DOI（如 ADAURA 曾写成 NEJMoa2027086）比没有 DOI 更糟。
