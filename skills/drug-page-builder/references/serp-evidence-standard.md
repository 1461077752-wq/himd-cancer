# SERP 需求取证标准（下拉词 → 卡面 / 章节 / FAQ）

目的：卡面和长尾问题**来自真实搜索需求**，不来自编辑直觉。需求证据与事实证据严格分离（事实证据见 source-hierarchy.md）。

## 一、六引擎采集法

| 项 | 规则 |
|---|---|
| 引擎 | 百度 PC 接口、百度移动、Bing、Google、360、搜狗，共 6 个（神马返回 403，不纳入） |
| 种子 | 分 4–6 批：核心别名（通用名/商品名/研发代号/常见误写）/ 疑问前缀（能不能/怎么/多久/是什么）/ 症状词 / 支付词（医保、报销、价格、惠民保）/ 治疗场景（术后、耐药、脑转移、漏服）/ 英文词 |
| 规模参照 | 基准采集 62 种子 → 1,266 条含药名唯一建议词、2,513 个出现槽位 |
| 强度口径 | **引擎共识度** = 该词出现在几个引擎的下拉列表。**它是需求强度代理，不是搜索量**，页面与文档不得写成「多少人在搜」 |
| 分级 | S 级 = ≥5 引擎；A 级 = 4 引擎；槽位数用于同级内排序 |
| 留档 | 采集脚本与原始返回必须落盘可复现；结论表进 `src/content/audit/<slug>/serp-keywords.yaml` |

时效：下拉词有保质期（09-11 定的卡在 09-16 已被「说明书」「是几代」反超）。**每页开工时重采，不沿用他药数据，隔期更新前重采**。

## 二、serp-keywords.yaml 记录规范

块式 YAML（流式 `- {…}` 解析器不认）。每条入选/拒绝记录：

```yaml
selected_queries:
  - evidence_id: bd-m-ob-001
    query: 奥希替尼医保报销后价格
    surface: dropdown          # dropdown|related|paa|suggestion|site_search|search_console|volume_tool
    engine: baidu_mobile
    seed: 奥希替尼医保
    slots: 6
    consensus: 5
    source_url: "https://…"    # 可复核来源页；URL 的查询词必须 == seed
    collected_at: "YYYY-MM-DD"
    used_in: [card-4, section-费用]
rejected_queries:
  - evidence_id: …
    query: …
    reason: …                  # 噪声/串词/错误前提/已由正文承接不上卡面
```

硬规则（与疾病页同源，全部适用）：

1. **候选词自身的搜索结果页不是需求证据**。证据必须来自以药名为 seed 的下拉/相关/PAA 返回；`source_url` 查询词与 `seed` 不一致即无效，发现标错移入 `rejected_queries` 并注 `invalidated_record`，不许改注释后继续用同一 evidence_id。
2. 直接 `query` 搜索页只证明「执行过一次查询」，不得用于卡面、FAQ、模块选型。
3. 量化工具/Search Console/站内搜索可作需求证据，但要记数据源、地区、时间范围，不得伪装成 SERP 表面。
4. **被拒问题不得回流**：不进标题、FAQ、正文、摘要、锚文本，也不以「误区纠正」名义复活。

## 三、需求 → 页面结构的映射

1. **先聚主题簇再选位置**。基准药 12 簇：副作用应对 24.1% / 费用医保 20.1% / 耐药 8.1% / 疗效 7.9% / 相互作用忌口 7.8% / 用法漏服 7.2% / 转移场景 6.9% / 身份说明书 6.5% / 同类药 5.9% / 检测复查 4.6% / 特殊人群 0.7% / 决策心理 0.3%。簇占比决定正文哪节必须厚、FAQ 往哪倾斜，**不决定卡面**——卡面过四道闸门（card-selection-protocol.md）。
2. **逐条做「需求 × 页面覆盖」对照表**，判定 ✅/🟡/❌。🟡 的高危形态要特别抓：答非所问（问「皮疹用什么药」答「保湿防晒」——用户问药，页面给护理）、只给清单不给对比、断言超出证据（「报销范围与 5 项适应症一致」）。
3. **别名词是独立需求**：商品名、研发代号（9291）、误写（奥西替尼）、英文名各成一问，至少要被 FAQ 或身份区承接——读者需要在页面上「认出自己搜的词」。
4. **语气敏感词降级**：「能活多久」「会不会加速扩散」类高需求词，需求本身成立，但措辞不进标题；语义由答案和正文接住，问句改写或收进 FAQ。
5. 负面与安全感类问句（有辐射吗、对家人有影响吗）：不进卡面，正文/FAQ 给直答，不贩卖焦虑也不回避。

## 四、缺证据时的处理

无 SERP 数据、无法联网重采时：**不得凭常识伪造下拉词**。可以照常写说明书/指南驱动的内容层，但卡面若沿用其他页面的问题清单，必须在 `audit/<slug>/` 记「未经本药需求取证」，页面不渲染该说明、进度表标注待复核。缺证据只暂停该药的卡面选型，不阻塞正文研究。
