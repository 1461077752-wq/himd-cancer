# 药品页内容深度标准

用于保证生成页覆盖「一份说明书 + 对手百科 + 丁香园」的全部主题，并在患者决策层超出两者。这是覆盖检查，不是要求所有药机械使用相同小标题。**不得用字数代替深度**：长篇定义、重复免责声明、药名堆砌不算厚度；厚度来自条件、分叉、例外、可执行行动和可核查来源。

## 一、先建覆盖矩阵

开工前列内部矩阵，行 = 下面 A–S 维度，列 = 是否适用 / 患者核心问题 / 正文落点 / 来源层级（S1–S5）/ 排除理由。不适用项（如非肿瘤药的「耐药」）必须写排除理由，不许留空标题占位。

| # | 维度 | 具体要求 |
|---|---|---|
| A | 药品身份 | 通用名/商品名/英文名/别名/研发代号/厂家/类别/剂型；**别名必须出现在 H1、titleTag 或 FAQ 至少一处**（用户拿俗称搜进来要认得出） |
| A2 | 化学档案 | 分子式、分子量、CAS——可只进数据留存（`archive`），页面是否展示按药决定 |
| A3 | 规格与监管标识 | 规格、批准文号、执行标准、贮藏、有效期；`spec` 字段与正文至少一处呼应 |
| B | 适应症全量 | 逐条获批适应症 + 各自获批年份；区分「药监批准人群」与「可能获益人群」 |
| B2 | 监管时间线 | 全球/中国首获批、进医保、进基药、专利/降价节点（`timeline` 或正文表格） |
| C | 用法用量 | 标准剂量、给药方法、与进食关系、固定时间 |
| C2 | 剂量调整 | 暂停/减量/永久停药的触发条件，逐条列 |
| C3 | 特殊给药操作 | 吞咽困难、鼻胃管分散操作与冲管 |
| C4 | 特殊人群剂量 | 肝损/肾损/老年/儿童/体重 |
| D | 不良反应全量 | 常见反应发生率表 + 化验异常 + 3~4 级与老年差异；**每个发生率带来源与分母口径** |
| E | 严重风险警示 | ILD/QTc/心肌病/角膜炎/VTE 等；页面**唯一**强对比色块（danger-band）承载 |
| F | 禁忌 | 独立成表，不埋在正文段落里 |
| G | 相互作用 | 按「会加快分解的 / 会减慢分解的 / 会打乱心电图的 / 会互相抬高的」患者语言分组；西柚等食物相互作用不能缺席 |
| H | 特殊人群 | 妊娠、哺乳、避孕时长、生育、儿童、老年，逐组给结论 |
| I | 药代动力学 | 半衰期、蓄积、食物/抑酸药影响、代谢酶——全部落到「对你意味着什么」（漏服窗口、起效节奏） |
| J | 药理 | 靶点、选择性、活性代谢物；一句话能讲清的机制放最前 |
| K | 关键疗效数据 | 每项注册研究一组数字；汇总表 + 各研究细节 |
| K2 | 亚组 | 脑转移/CNS、中国亚组、ORR、缓解持续时间 |
| L | 耐药 | 机制百分表（分线次）+ 中国已获批后线 + 检测路径（组织 vs ctDNA）+ 在研代次 |
| M | 价格与医保 | 原研/仿制并列、报销比例**方向写清（报销 not 自付）**、分省算例、办理路径（去哪办、带什么、多久生效） |
| M2 | 目录与可及 | 医保乙类/甲类、基药、双通道、惠民保口径 |
| N | 同类药对比 | 横向表：品种/厂家/适应症差异/医保状态；**是差异维度对照表，不是清单**；配「不构成选药建议」 |
| O | 日常实务 | 复查频率与项目、疫苗、饮食忌口、驾驶、储药、忘带药、自行停药场景 |
| P | 长尾 FAQ | ≥15 条，覆盖俗称/误写/价格/停药/忌口/生存期解读 |
| Q | 来源可核查 | ≥15 条、一手 ≥5、逐条带 kind 与日期 |
| R | 机器可读 | Drug/MedicalWebPage/BreadcrumbList/FAQPage 自动生成，无需手写 |
| S | 患者决策支持 | 首屏直答卡、节内行动出口、买药/招募入口 |

## 二、三层结构

1. **患者直答层**（前 6–7 个 H2）：是否适用→疗效→费用→医保→购买→仿制药→怎么吃→副作用→耐药，按患者决策链排序。
2. **说明书级专业层**（tier:'pro' 章节）：剂量调整、相互作用、禁忌、特殊人群、药代、随访——表格化、逐项标注来源。
3. **独家层**（对手没有的）：中国逐条获批时间、同类药真对比表、价格医保测算与办理路径、耐药机制百分表与后线、诚实不确定性标注。

## 三、章节写法硬性要求

- **问句标题下第一句 = 加粗直答**。写不出可判真假的第一句，说明该节还没研究完，先补证据再写。「本节介绍……」「随着……」开场视为未完成。
- **正面回答优先于否定式**：「哪里能买」的首句不能是「买不到」——先给渠道（凭处方在医院/定点药房取药），限制条件退到第二句，结尾把否定转成可达路径。
- **语气优先于关键词**：「能活多久」类问句改「生存期能延长多少」——主语从读者换到治疗。搜索语义能对上，刺眼措辞的代价由每位读者承担。此规则适用于标题、卡面、首页文案；下拉词原话进入标题前过一遍语气检查。
- **每个 H2 节末两个固定件**：定制免责 `.section-caveat`（按该节内容分别措辞，11 句不重样；重复收尾本身是 AI 文本特征）+ 来源 `.source-note`。顺序固定「免责 → 来源」。
- **专业字段进第二层时每条带一句「对患者意味着什么」**；纯抄说明书字段不算深度。
- **表格克制使用**：列名与内容必须相符；三列及以上长文本表会被压成两行折字（「医院没药」→「医院没/药」），此时改叙述或有序列表。清单式材料（「什么情况→怎么办」）本质是叙述，别硬做表。
- **数字带 `.stat-band`** 只放该节主结论数字，与卡面/FAQ 同值（见 source-hierarchy.md）。
- **不渲染更新日期**：`updatedAt` 只进审计与 JSON-LD；页面、卡面、节末都不出现「更新日期/核验日期/最后更新」。来源自带的版本年份（「2025年版」「（2025-10）」）保留，那是来源属性。
- **内部流程词禁入患者可见文本**：`stat-band`、`danger-band`、`labelFacts`、`quickAnswers`、`anchor`、`SERP`、`下拉词`、`槽位`、`引擎共识度`、`证据表`、`待补` 等一律不进正文与卡面。判断法：没参与过本项目的患者读到这句话能不能懂。
- **禁用批量 sed 替换医疗文本**；改写数字必须逐处对照 numbers.json。

## 四、量化验收线（低于任何一条即未完成）

- 中文字符 ≥ 10,000（frontmatter + 正文合计口径；基准页 13,298）
- 正文表格 ≥ 6；FAQ ≥ 15 且与卡面问句无完全同问；来源 ≥ 15、一手 ≥ 5
- 每个发生率/价格/生存期数字可指回 numbers.json 条目
- danger-band 全页唯一
- 320 / 360 / 390 / 428 / 768 / 1280 / 1440px 实测 `scrollWidth == clientWidth`
- 目录与卡面锚点 0 断链（锚点解析规则见 data-field-guide.md）
- 每个 H2 有定制免责 + 节末来源
- 「更新日期/最后更新」在渲染 HTML 中出现 0 次
