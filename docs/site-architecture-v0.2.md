# 网站整体架构方案 v0.2（讨论稿）

> 状态：讨论中，待拍板品牌域名 / en 站节奏 / 登记表单 / 医学审核人后进入 P0
> 日期：2026-09-10
> v0.2 变更：按"页面克制三原则"重构——单页极致替代 Hub+子话题、服务平台定位、顺序极致推进；独立 QA 页与科普文章集合移出范围。需求侧详见 `docs/prd-site-v0.2.md`。

## 一、定位与目标

面向癌症肿瘤患者的疾病科普 + 药品信息 + 临床试验招募平台。

**产品口径**：专业可靠的患者**服务平台**，不是资讯科普平台——每个页面都是服务入口，全站围绕患者旅程组织：了解疾病 → 认识药物 → 评估报名。

**核心目标**：当用户在 Google 和 Bing 搜索任何癌种名称、药品名称相关问题时，我们的页面在搜索结果中拿到最前列排名。

**已拍板决策**：

| 决策项 | 结论 |
|---|---|
| 市场与语言 | 中英双语全球覆盖（zh 站根路径 + en 挂 /en/ + hreflang 双向声明） |
| 招募业务 | 临床试验招募，对接 CRO/药企项目（非海外就医中介、非自有患者登记） |
| 内容生产 | AI 初稿 + 医学专家审核后发布（审核署名同时是 E-E-A-T 核心证据） |
| 站点载体 | 本项目（cancer）全新建站；himd-astro 已验证的疾病页模板模式（Hero 信息卡+分节）迁移复用 |
| 页面克制三原则（2026-09-10） | ① 页面数量克制，每页做到完美，疾病页不拆 Hub+子话题 ② 服务平台定位，暂不做科普文章 ③ 第一个页面做到极致 → 沉淀标准 → 按标准做下一个 |

**核心思路**：SEO 不靠页面数量取胜，而是**每个页面吃透一个主题的完整关键词簇**——病种/药品各一个极致单页，主干词、别名、长尾问句全部收编进页面分节与 FAQ，配合审核署名的 E-E-A-T 建立单页权威度。

## 二、URL 与双语体系

```
/                                    zh 首页（服务平台入口，无前缀）
/diseases/lung-cancer/               zh 疾病极致单页（分节以页内锚点呈现）
/drugs/osimertinib/                  zh 药品单页
/trials/                             zh 招募索引
/trials/lung-cancer/                 zh 病种招募列表
/trials/nct04179517/                 单个试验页
/en/…                                英文树，与中文树同构
```

- **不设子话题路由**：症状/诊断/治疗等以疾病页内分节呈现，锚点 URL（如 `/diseases/lung-cancer/#survival`）可直达、可被站内外引用
- Astro 原生 i18n 路由：`zh` 无前缀、`en` 挂 `/en/`，每个语言树独立 sitemap 分片
- `<link rel="alternate" hreflang>` 双向声明，`x-default` 指 zh
- 每个关键词只对应一个 canonical 页，杜绝中英版本互相竞争

## 三、内容模型（四类集合）

| 集合 | 数据来源 | 模板关键分节（患者关注点优先） |
|---|---|---|
| `diseases` 疾病 | AI 草稿+人工审核 | Hero 信息卡直答 → 页内目录 → 症状/诊断/治疗/生存率/费用 → FAQ（长尾问句收编）→ 相关药品 → 招募入口 |
| `drugs` 药品 | 说明书+指南+AI 草稿 | 是什么药/治什么 → 疗效数据 → 价格与医保 → 副作用应对 → 同靶点替代药 → 该病招募入口 |
| `trials` 试验 | ClinicalTrials.gov API 自动同步 | 治什么病用什么药 → 入排标准翻译成人话 → 地点 → 受试者费用与权益 → 申办方资质 → 报名入口 |
| `aliases` 别名库 | 人工维护 | 每个药品登记：通用名/商品名/英文名/俗名 |

- **独立 QA 页与科普文章集合暂不做**：长尾问句由疾病/药品页 FAQ 分节收编，不再单独建页
- **别名库是中文 SEO 的隐藏金矿**：患者搜"9291"比搜"奥希替尼"多得多（同理 K药/O药）。把全部别名覆盖到该药品唯一页面的标题、H1 和 FAQ，实现"同药多词霸屏"——与单页极致原则天然一致

**量级估算**：病种页 ~120（含亚型）+ 药品页 ~400 + 试验页按同步项目数，初期合计 500 页量级。推进方式为**顺序极致**：首个页面做到极致并沉淀标准，之后按标准逐页复制，不设铺量指标。

## 四、内容流水线（AI 初稿 → 专家审核 → 极致标准检查 → 发布）

```
数据源(NCCN/SEER/GLOBOCAN/CSCO/卫健委/药品说明书)
  → AI 按模板出初稿
  → 医学专家审核（不通过退回）
  → 极致标准清单检查（首个页面沉淀的 SOP，逐项过检）
  → 发布（前台署名：审核人+审核日期+引用源）
  → 每季度复审刷新
```

- 内容 schema 必备字段：`status (draft / reviewing / published)`、`author`、`reviewedBy`、`reviewedAt`、`sources[]`
- 未过审核或未过极致标准的页面**不进 sitemap、不渲染公开路由**——宁可不上线，不可不完美
- 首个病种页 + 首个药品页即标准样板：打磨到位后固化为《页面极致标准清单》，后续页面按此复制
- 试验页自动化通道：API 同步 → 规则过滤（肿瘤 + Recruiting 状态 + 目标地区）→ 生成草稿 → 人工把入排标准改写成患者语言 → 发布

## 五、SEO 执行体系

### 1. 单页关键词簇策略

| 词型 | 落位 |
|---|---|
| 疾病/药品主干词 | 页面标题与 H1 |
| 药品俗名/别名 | 标题、H1、FAQ（别名库驱动） |
| 长尾问句（"肺癌五年存活率"） | FAQ 直答 + 对应分节锚点（可抢 FAQ 精选摘要） |
| 招募词 | 页面招募入口 + /trials/ 列表页 |

### 2. 关键词三梯队（决定页面推进顺序与覆盖优先级）

| 梯队 | 词型 | 示例 | 判断 |
|---|---|---|---|
| 第一梯队 | 药品俗名/别名、长尾问句、招募词 | "9291"、"肺癌五年存活率"、"奥希替尼价格" | Quick Win：首批页面必须全量覆盖 |
| 第二梯队 | 疾病主干词中文 | "肺腺癌"、"胆管癌" | 靠病种单页权威度主攻 |
| 第三梯队 | 英文核心词+中文头部词 | "lung cancer"、"肺癌" | Big Bet：6~12 个月攻坚 |

### 3. E-E-A-T 资产（YMYL 领域生死线）

Google 把医疗内容归为最高风险等级（YMYL）。新站必须具备：

- 医学审核团队页（真实资质、执照、照片）
- 作者页、编辑政策页、关于我们（服务说明与联系方式）
- 全站医疗免责声明
- 每个数据点标注权威来源（NCCN / SEER / GLOBOCAN / CSCO / 卫健委 / 药品说明书）

没有真人审核署名，技术做得再好也排不上去。

### 4. 结构化数据映射

| 页面 | Schema |
|---|---|
| 疾病页 | `MedicalWebPage` + `MedicalCondition` + `FAQPage` |
| 药品页 | `Drug` |
| 试验页 | `MedicalTrial` |
| 全站 | `Organization` + 审核人 `Person` |

目标是抢 Google/Bing 富摘要位置。

### 5. 内链规则

- 疾病 ↔ 药品 ↔ 招募网状互链 + 全程面包屑
- 页内锚点直达分节，锚点 URL 可被站内外直接引用
- 单页策略下权重不依赖子话题汇入，靠页面深度与外链积累

### 6. 提交与索引

- Google Search Console + Bing Webmaster Tools + **IndexNow**
- IndexNow 实现 Bing 秒级收录；Bing 是新站最容易先出排名的战场，且供给 DuckDuckGo/Yahoo 流量

### 7. 外链起步

患者社群合作、医疗垂直目录、行业媒体报道，外链集中投向核心页面。

### 8. 现实预期

- 头部词（"肺癌"）对手是默沙东、Mayo、丁香园，新站短期不打
- 单页策略下每页都是主战场：FAQ 与锚点长尾问句 3~6 个月起量，头部词 6~12 个月攻坚

## 六、合规红线

- 全站声明"信息不构成医疗建议，用药遵医嘱"
- 招募页必须标注申办方、伦理批件、知情同意说明，不承诺疗效
- 涉及患者健康信息的表单按个保法/HIPAA 标准设计（加密+授权文案）
- 药品信息严格以官方批准说明书为准
