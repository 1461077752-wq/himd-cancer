# 药品页信息厚度对标 v0.1（奥希替尼）

> 日期：2026-09-11
> 目的：以丁香园用药助手奥希替尼页与百度百科奥希替尼词条为基准，量化本站药品页的信息差距，并给出"超越"的可验收标准。
> 关联文档：`docs/prd-site-v0.2.md` 3.2 药品极致单页、`docs/site-architecture-v0.2.md` 三、五

---

## 一、结论摘要

1. **差距主要不在"患者语言"，而在"专业层缺一整层"。** 本站现有 6 个正文章节覆盖了患者最关心的六件事（适用、服用、副作用、疗效、费用、耐药），但**说明书级字段几乎全缺**：不良反应完整发生率、禁忌、药物相互作用、特殊人群、药代动力学、药理毒理、贮藏与执行标准、批准文号。
2. **量化差距约 2~3 倍。** 本站奥希替尼页中文字符总量约 **4,700 字**（正文 2,770 + Frontmatter 1,940）；而一份完整说明书正文约 **7,000~10,000 字**（以中国医药信息查询平台收录的同品种说明书实测 6,992 中文字符为下限），且丁香园在此之上还有用药问答与价格栏目。
3. **百度百科的厚度是"另一种厚度"**：医学内容薄且停留在 2016 年口径（仅 T790M 后线），但补了本站没有的**化学与监管档案**——分子式、分子量、立项人、获批时间线、基药目录动态、国内同类药竞争格局。
4. **超越路径不是"堆字"，而是"两层结构"**：患者层（对手没有）+ 说明书级专业层（对手有但我们缺）+ 独家维度（同类药横向对比、中国价格医保测算、耐药机制与后线路径、分诊与决策支持）。堆到对手同样的字数只是及格线；**在其文档结构之上多出可被引用的独立事实**，才叫超越。

## 四、超越策略

### 4.1 三层结构（层级即答案）

| 层 | 面向 | 内容 | 对手情况 |
|---|---|---|---|
| 第一层 患者直答 | 刚拿到药的患者/家属 | 是否适用 → 怎么吃 → 副作用 → 疗效 → 费用 → 耐药（现有 6 节） | 两家都没有 |
| 第二层 专业细节 | 想核对说明书、要跟医生讨论的人 | 说明书级全字段，表格化、可折叠、逐项标注来源 | 丁香园有，百度百科基本没有 |
| 第三层 独家维度 | 做决策的人 | 同类药横向对比表、中国价格医保测算、耐药机制与后线、日常实务、长尾 FAQ | 两家都没有 |

### 4.2 只在"有增量"的地方投入

1. **补全但不照抄**：说明书字段进入第二层时，每条都要有"对患者意味着什么"的一句话解释——这是丁香园不做、患者最缺的部分。
2. **把百科的档案变成可引用事实**：化学标识、获批时间线、基药目录、同类药格局，全部落到带来源的表格，而不是散在正文。
3. **横向对比表是最大单点增量**：三代 EGFR-TKI 全部品种、厂家、适应症、医保状态一表看清，两家都没有完整版。
4. **中国价格医保测算**：原研/国产/基药/援助四路并列，标注口径日期，比丁香园的单一"参考价"更可用。

### 4.3 可验收标准（发布前逐项过检）

- [x] 中文字符总量 ≥ 10,000（当前 4,708 → **13,298**）
- [x] 第三、四节对比表中标 ❌ 的维度全部消除
- [x] 正文表格 ≥ 6 个（当前 0 → **15**）
- [x] FAQ ≥ 15 条（当前 8 → **15**，另有首屏直答 4 条），覆盖"9291/泰瑞沙/奥西替尼/奥希替尼"四个写法与主要长尾问句
- [x] 来源 ≥ 15 项（当前 8 → **18**），且至少 5 项为一手来源（NMPA 说明书、FDA 说明书、NEJM 原文、国家药监局公告、医保与基药目录文件）
- [x] 每个发生率数字标注来源或"说明书临床试验数据"口径
- [x] 危险信号（间质性肺病、QTc、心肌病、角膜炎）为页面唯一强对比色块
- [x] 移动端无横向滚动（320 / 360 / 390 / 428 / 768 / 1280px 实测 `scrollWidth == clientWidth`）

**四、逐节免责**
11 个 H2 小节各加一条定制免责（`.section-caveat`，品牌色浅底 + 左侧竖条），措辞按该节内容分别写，避免同一句重复 11 次（重复收尾本身就是 AI 文本特征）：
- 适用性 → 「取决于你的基因检测结果和分期，以主治医生的判断为准」

- 副作用 → 「不能替代医生的诊疗意见，出现严重不适请立即就医」
- 疗效 → 「人群统计，不能预测某个人的结局」
- 费用 → 「以当地医保部门和医院的实际结算为准」
- 耐药 → 「必须由医生结合影像复查和再次检测判断」

- 说明书 → 「以药盒内说明书和医生嘱咐为准」

### 5.0 教训：不要用自造比喻替换行业常用词

### 5.0 侧栏消失的真因：`.hidden{display:none!important}`

接入 HIMD 站点外壳时，为了兜住 `.desktop-menu-solutions` 等弹层的隐藏，在 `site-chrome.css` 里写了**全局** `.hidden{display:none!important}`。这条 `!important` 会压过本项目所有 `hidden lg:block` 的响应式写法——`<aside class="hidden lg:block">` 因此**在任何宽度下都是 display:none**，右侧栏（导航 / 可靠性 / 购药入口）整块消失。

```css
.desktop-menu-solutions.hidden,
.navbar-mobile-dialog.hidden,
.navbar-mobile-submenu.hidden { display: none !important; }
```

教训：从外部项目搬 CSS 时，通用类名（`.hidden`、`.sr-only` 之类）**必须收窄到自己的作用域**，否则会污染本项目的既有工具类。
