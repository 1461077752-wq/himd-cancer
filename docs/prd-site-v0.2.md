## 1. 背景与目标

### 1.1 背景

- **患者侧现状**：癌症患者及家属确诊后的第一反应是搜索——搜病名、搜药名俗名（"9291""K药"）、搜生存率和费用。中文搜索结果中权威内容稀缺且分散：头部词被药企官网、Mayo/默沙东类机构内容占据，长尾问句则充斥过时信息和广告，患者难以获得可信、可读的答案。
- **供给侧现状**：公司已通过 himd-astro 验证了"Hero 信息卡 + 分节"疾病页模板模式，具备 AI 辅助内容生产能力，且拥有 CRO/药企临床试验项目合作渠道（招募业务定位已拍板：对接 CRO/药企，非海外就医中介、非自有患者登记）。
- **产品原则（2026-09-10 拍板）**：页面克制三原则——① 每个页面做到完美，疾病页不拆 Hub 与子话题；② 服务平台定位，不是资讯科普平台，暂不做科普文章；③ 第一个页面做到极致后沉淀标准，按标准逐页推进。本 PRD 全部设计按此原则执行。
- **为什么是现在**：长尾问句词竞争低、意图强，可由极致单页的 FAQ 与分节直接覆盖；Bing/IndexNow 为新站提供快速收录通道；医疗内容（YMYL）的 E-E-A-T 门槛决定了"AI 初稿 + 真人医学审核署名"是唯一可规模化且可信的内容供给方式——这套生产要素当前都已具备。
- **不做会怎样**：招募获客持续依赖付费投放，成本高且不沉淀资产；做了，搜索自然流量成为可复利的获客资产，招募转化形成闭环。

## 2. 需求概述

以专业可靠的患者服务平台定位，为每个病种/药品打造一个覆盖其全部搜索意图的极致单页，经医学专家审核署名后发布；首个页面做到极致后沉淀标准，按标准逐页推进，抢占搜索排名并沉淀临床试验报名线索。

## 3. 功能详细设计

### 3.1 疾病极致单页

**功能描述**：一个癌种（含亚型）一个页面，页内锚点目录承载全部患者关注分节，成为该病种的一站式答案页。
**用户故事**：作为新确诊患者的家属，无论我搜"肺腺癌五年存活率"还是"肺腺癌化疗后白细胞低吃什么"，都希望落在一个页面里直接找到答案。
**优先级**：模板与极致标准框架 P0；首个病种页极致化 P1；按标准逐页复制 P2。

**业务规则**：
1. 每个癌种（含亚型，如肺腺癌）对应唯一页面，URL 形如 `/diseases/{病种}/`；不设任何子话题路由，症状、诊断、治疗等以页内分节呈现。
2. 页面结构固定：页内目录（锚点导航，与分节一一对应）→ Hero 信息卡直答（患者最关心问题 + 数据直答）→ 症状 → 诊断 → 治疗 → 生存率 → 费用 → FAQ → 相关药品 → 招募入口。
3. 每个分节对应一个患者关注主题，分节锚点 URL（如 `/diseases/lung-cancer/#survival`）可直达、可被站内外引用。
4. FAQ 覆盖该病种关键词矩阵中全部第一梯队问句；新问句一律并入 FAQ 或扩写对应分节，不另建页。
5. 每个数据点必须标注权威来源（NCCN / SEER / GLOBOCAN / CSCO / 国家卫健委指南 / 药品官方说明书），无来源数据不得发布。
6. 发布前置双 gate：医学审核通过 + 《页面极致标准清单》全部通过；任一未过则不进 sitemap、不渲染公开路由、直接访问返回 404。
7. 相关药品模块仅列出该病种已发布药品页，按与该病种治疗方案的关联度由编辑人工审定排序；无已发布药品页时不渲染该模块。
8. 招募入口仅在存在该病种在招试验时渲染；无在招试验则不渲染，不留空模块。

**交互流程**：
1. 用户从搜索引擎进入（若搜索词命中某分节，页面定位到对应锚点）
2. Hero 信息卡直答核心问题（如五年存活率数据）
3. 通过页内目录跳转到关注分节，或顺序阅读
4. FAQ 点击展开查看问答
5. 底部点击相关药品进入药品页，或点击招募入口进入病种招募列表
6. 成功：页面完整渲染、锚点可达；失败：未发布页面返回 404

**异常处理**：

| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 审核不通过 | 退回编辑改写，页面保持不可见 | 无（页面不存在于公开侧） |
| AI 初稿数据与权威源冲突 | 审核人标记强制核对项，核对完成前不允许通过审核 | 无 |
| 权威指南更新 | 进入季度复审队列，刷新后更新页面与标注日期 | 页面展示"更新于 X 年 X 月" |
| FAQ 问句与分节内容重复 | 以分节为准，FAQ 保留简答并锚点引用对应分节 | 用户无感知 |
| 单节内容过载影响可读性 | 采用折叠分层或表格式呈现，移动端走查通过后才可过极致标准 | 用户无感知 |

### 3.2 药品极致单页与别名库

**功能描述**：每个药品一个 canonical 极致单页，覆盖疗效、价格医保、副作用、替代药；别名库将俗名/商品名全部收编到同页，实现"同药多词霸屏"。
**用户故事**：作为治疗中的患者，我搜"9291 价格"时希望直接落在讲奥希替尼的完整页面，以便确认这药治什么、多少钱、有什么替代选择。
**优先级**：模板与别名库机制 P0；首个药品页极致化 P1；逐页复制 P2。

**业务规则**：
1. 每个药品对应唯一 canonical 页；该药登记的全部别名（通用名/商品名/英文名/俗名）须出现在页面标题、H1、FAQ 至少一处。
2. 一个别名只能归属一个药品页；当同一俗名可能指向多个药品时，由编辑人工裁决唯一归属，其余相关药品通过"其他名称"字段列出该别名，但不作为主别名。
3. 页面分节顺序固定：是什么药/治什么病 → 疗效数据 → 价格与医保 → 副作用应对 → 同靶点替代药 → 该病种招募入口。
4. 药品信息严格以官方批准说明书为准；价格与医保信息标注地区与查询日期，无公开价格时明确写"以定点医院/药房实际价格为准"。
5. 副作用应对分节固定包含"出现严重不适请立即就医"提示，不构成用药指导。
6. 发布前置双 gate 同 3.1 规则 6。

**交互流程**：
1. 用户搜索俗名（如"9291"）命中药品页
2. Hero 直答"是什么药、治什么病"
3. 依次查看疗效、价格医保、副作用应对
4. 底部进入同靶点替代药或该病种招募入口
5. 成功：页面完整渲染；失败：目标药品页未发布则 404，页面不渲染指向它的链接

**异常处理**：

| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 搜索的药品尚未建页 | 不渲染占位薄页，按标准排期覆盖 | 无（搜索引擎侧无低质页面） |
| 说明书版本更新 | 触发该药品页复审，更新后标注日期 | 页面展示"更新于 X 年 X 月" |
| 同靶点替代药未发布 | 药品页不渲染该链接，不留站内死链 | 用户无感知 |
| 别名归属争议 | 编辑人工裁决后入库，裁决记录留存 | 用户无感知 |

### 3.3 招募服务板块（服务闭环核心）

**功能描述**：全站服务闭环的核心承接——患者从疾病/药品页进入，看懂试验、评估自身条件、提交报名意向，形成"信息 → 评估 → 报名"的服务链路。
**用户故事**：作为寻求新疗法的患者，我希望用大白话看懂"我符不符合条件、要去哪、要不要花钱"，以便决定要不要报名。
**优先级**：招募索引与列表骨架、意向表单 P1；试验页自动化流水线 P2。

**业务规则**：
1. 试验数据自动同步 ClinicalTrials.gov，同步频率每日一次（建议值，待拍板）；同步字段包含：试验状态、入排标准、开展地点、申办方、试验分期。
2. 准入过滤规则固定为三条同时满足：肿瘤领域 + 招募中（Recruiting）+ 开展地区包含目标地区（目标地区范围待拍板，默认中国大陆）。
3. 详情页分节顺序固定：治什么病用什么药 → 入排标准（患者语言改写版 + 原文折叠）→ 开展地点 → 受试者费用与权益 → 申办方资质 → 报名入口。
4. 入排标准必须经人工改写为患者语言后方可发布；仅机器同步生成的草稿不渲染公开路由。
5. 详情页固定标注：申办方名称、伦理批件信息（数据源缺失时标注"以知情同意书为准"）、知情同意说明；全文不得出现疗效承诺用语。
6. 试验状态变更为非 Recruiting 时：列表页不再展示该试验；详情页顶部展示最新状态，且不渲染报名入口。
7. 报名转化 P1 采用轻量意向表单：必填项为称呼、联系方式、所患癌种，选填项为近期治疗情况；完整患者登记功能待拍板后迭代。表单提交成功生成线索记录并通知运营（通知方式待定）。

**交互流程**：
1. 用户从疾病/药品页招募入口或搜索引擎进入病种招募列表
2. 选择试验进入详情页，阅读改写后的入排标准
3. 点击"报名/咨询"进入意向表单
4. 填写必填项并勾选授权文案后提交
5. 成功：展示提交成功反馈，线索进入后台；失败：行内提示错误字段，用户输入保留

**异常处理**：

| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 数据同步失败 | 沿用上一次同步数据，后台告警通知编辑 | 无 |
| 表单必填项缺失 | 拦截提交，行内标注缺失字段 | "请填写称呼/联系方式/所患癌种" |
| 短期重复提交 | 同一联系方式 7 天内对同一试验的提交合并为一条线索 | 提示"我们已收到您的报名" |
| 表单服务不可用 | 保留用户已填内容，禁止清空 | "提交失败，请稍后重试，您填写的内容已保留" |
| 试验中止/状态变更 | 自动更新状态标注、撤下报名入口 | 顶部展示"该试验已结束招募" |

### 3.4 首页与全局导航

**功能描述**：服务平台的门面——病种/药品服务入口、招募服务入口、信任要素，不承载资讯内容。
**用户故事**：作为患者家属，我希望打开首页就能找到我关心的病种入口和"有没有我能参加的试验"。
**优先级**：P0。

**业务规则**：
1. 首页核心区块固定：病种服务入口（按部位/系统分组）→ 药品别名速查 → 招募服务入口 → 信任要素（审核团队、资质、合作说明）。
2. 首页不设文章列表、资讯流等资讯平台区块，强化服务平台感知。
3. 全局导航固定四项：疾病、药品、临床试验招募、关于我们（审核团队/编辑政策/免责声明）。
4. 首页各入口仅展示已发布页面；未发布的病种/药品不出现，避免空壳入口。

**异常处理**：

| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 病种/药品页下线 | 首页对应入口同步移除 | 用户无感知 |
| 病种/药品页新发布 | 首页对应入口自动出现，无需人工维护入口列表 | 用户无感知 |

### 3.5 双语体系（zh 默认 + en 子树）

**功能描述**：中文为主树，英文挂 /en/ 同构子树，服务全球中英文搜索用户。
**用户故事**：作为海外华人患者或英文使用者，我希望切换语言后看到同样结构的内容，以便在自己熟悉的语言下获取信息。
**优先级**：双语路由底座 P0；en 核心页 P2；en 铺开 P3（铺开节奏待拍板，建议核心页先行、看数据再全量）。

**业务规则**：
1. zh 为默认语言、URL 无前缀；en 统一挂 /en/ 前缀，目录结构与中文树同构。
2. en 页仅翻译已发布的 zh 页；en 未覆盖的页面在 en 树不渲染该路由，不留英文占位薄页。
3. 语言切换入口仅在该页 en 版已发布时展示；未发布则隐藏。
4. 中英页面互为 alternate 双向声明，x-default 指向 zh（验收见第 6 节）。
5. 同一关键词只对应一个 canonical 页，中英版本不互相竞争同一词。

**异常处理**：

| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 访问未发布的 en 路由 | 返回 404 | "页面不存在" |
| zh 页下线 | 对应 en 页同步下线，alternate 声明同步移除 | 404 |

### 3.6 内容生产与审核工作流（内部）

**功能描述**：AI 初稿 → 医学专家审核 → 极致标准检查 → 发布 → 季度复审的统一流水线，覆盖全部内容集合。
**用户故事**：作为医学审核人，我希望能逐条核对数据来源并一键通过/退回，以便对署名内容负责且不被流程拖垮产能。
**优先级**：P0（未审核不可发布是全站底线，P0 必须落地）。

**业务规则**：
1. 状态机固定：draft → reviewing → published；reviewing 状态被退回则回 draft；published 页进入季度复审队列。
2. 内容必备字段：status、author、reviewedBy、reviewedAt、sources[]；任一字段缺失时不允许提交审核或不允许发布。
3. 仅医学审核人可执行 reviewing → published 的流转；退回操作必须附修改意见。
4. AI 初稿中的生存率、剂量、价格三类高风险字段，审核时列为强制逐条核对项。
5. 页面复审到期时自动生成复审任务并通知审核人；复审通过则更新 reviewedAt，未处理则保留任务提醒直至处理。
6. 试验页自动化通道：API 同步 → 规则过滤（见 3.3 规则 2）→ 生成草稿 → 人工改写入排 → 发布，与人工内容共用同一状态机。
7. 审核人资质或署名信息发生变化时，须在下次内容发布前同步更新署名与审核团队页。
8. 《页面极致标准清单》由首个病种页与首个药品页打磨完成后固化；此后每个页面发布前逐项过检，未过项修复后重检，通过方可发布。
9. 页面推进遵循顺序极致原则：以最近一个达标页面为标准样板复制，不并行铺量；产能不足时优先保证在产页面的完善度，不牺牲质量换数量。

**异常处理**：

| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 审核不通过 | 退回编辑并附修改意见，页面保持不可见 | 无 |
| 极致标准检查未通过 | 列出全部未过项，修复后重检；检查完成前页面保持不可见 | 无 |
| 审核积压超过设定阈值（阈值待拍板） | 提示暂停新内容生产，优先消化存量 | 无（内部流程） |
| 已发布页面发现医学错误 | 立即下线为不可见状态，修复后重新走审核 | 访问返回 404 直至重新发布 |
| 审核人不可用（离职/中断合作） | 备份审核人接管；无可用审核人期间全站暂停发布 | 无 |

### 3.7 E-E-A-T 支撑页

**功能描述**：审核团队页、作者页、编辑政策页、关于我们、全站医疗免责声明五类页面，构成 YMYL 领域的信任资产与服务实体背书。
**用户故事**：作为搜索医疗信息的用户，我想看到回答问题的人是谁、有什么资质、这是个什么机构，以便决定是否信任这份内容和服务。
**优先级**：P0（支撑页须随 P0 上线，先于任何内容页发布）。

**业务规则**：
1. P0 上线时五类页面必须齐备：医学审核团队页（真实资质、执照、照片）、作者页、编辑政策页、关于我们（服务说明与联系方式）、全站医疗免责声明。
2. 每篇内容页底部固定展示：审核人姓名 + 资质链接 + 审核日期 + 主要来源列表。
3. 缺少可署名的真实医学审核人前，任何内容板块不进入公开发布阶段（对应待拍板事项 4）。
4. 全站页面（含招募页）底部固定展示医疗免责声明入口，声明"信息不构成医疗建议，用药遵医嘱"。

**异常处理**：

| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 审核团队页未上线 | 发布功能整体拦截 | 无（内部流程） |
| 某审核人资质信息待更新 | 该审核人名下页面暂停新发布，历史页保留原署名 | 用户无感知 |

### 3.8 站内导航与内链体系

**功能描述**：面包屑 + 疾病/药品/招募三类页面网状互链 + 页内锚点引用，构建单页深度型链接结构。
**用户故事**：作为从搜索直接进入内页的用户，我希望随时知道自己在哪、能去到相关的病种和药品，以便继续获取信息而非跳出。
**优先级**：P0（规则随模板落地）；P1 起全量执行。

**业务规则**：
1. 全部内容页展示面包屑，层级与 URL 结构一致（首页 → 栏目 → 页面），每级可点击返回。
2. 疾病页互链其相关药品页与招募列表；药品页链接其适应症疾病页与该病种招募列表。
3. 页内锚点 URL 可被站内其他页面直接引用（如药品页副作用分节链接至疾病页治疗分节锚点）。
4. 链接目标页未发布时不渲染该链接，站内不允许出现死链。
5. 目标页下线时自动移除全站指向它的链接，并生成编辑提醒任务。

**异常处理**：

| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 目标页下线 | 自动移除指向链接 + 生成编辑提醒 | 用户无感知 |
| 面包屑层级与 URL 不一致 | 视为模板缺陷，极致标准检查不通过 | 无 |

| 事件名 | 触发条件 | 关键属性 | 用途 |
|--------|---------|---------|------|
| page_view | 页面渲染完成 | 模板类型（disease/drug/trial）、语言、病种标识、药品标识 | 内容表现分层，与 GSC 展现/点击按 URL 对齐 |
| toc_anchor_click | 点击页内目录或分节锚点 | 来源页面、目标锚点 | 极致单页各分节关注度分析，指导分节扩写与 FAQ 覆盖 |

| recruit_form_start | 报名表单任一字段首次聚焦 | 试验编号 | 表单流失分析 |
| recruit_form_submit | 表单提交成功 | 试验编号、病种 | 有效线索核心指标 |
| form_error | 表单提交失败 | 错误类型（必填缺失/服务异常/重复提交） | 表单体验优化 |
| lang_switch | 点击语言切换 | 当前页面、目标语言 | en 内容需求验证 |
| source_outbound_click | 点击正文内权威来源外链 | 来源域名、页面类型 | 引用行为追踪，辅助 E-E-A-T 评估 |

### 5.2 外部数据源

GSC 与 Bing Webmaster Tools 的展现/点击/排名数据按 URL 与站内埋点对齐，作为收录与排名目标的核心监测源（见 1.3）。

### 5.3 实验与迭代机制

SEO 场景不做同页 A/B（避免中英/多版本互相竞争），采用分批上线对比：同一模板的口径或排序类改版（如 Hero 直答口径、FAQ 排序）分批发布，按批次对比 GSC 点击率，胜出版本固化为模板基线。
